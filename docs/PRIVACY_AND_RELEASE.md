# 1.7.1 隐私与上线检查清单

本文件对应 **App 1.7.1 / Schema 18**。目标是让“代码里的处理方式、微信后台填写内容、对用户展示的协议”保持一致。

## 一、提审前必须填写的云函数环境变量

在 `api` 云函数中至少配置：

```text
LEGAL_OPERATOR_NAME=真实运营者姓名或经营主体名称
LEGAL_PRIVACY_CONTACT=可实际收到消息的隐私联系邮箱/其他有效联系方式
LEGAL_SERVICE_CONTACT=客服联系方式
LEGAL_EFFECTIVE_DATE=2026-09-28
BETA_ENROLLMENT_ENABLED=true
DEFAULT_ADMIN_FRIEND_ENABLED=false
PRO_PURCHASE_ENABLED=false
```

如果 `LEGAL_OPERATOR_NAME` 或 `LEGAL_PRIVACY_CONTACT` 仍是默认占位内容，协议接口会返回 `productionReady=false`，仅用于提醒开发者，不建议提交审核。

## 二、小程序内已经实现的合规闭环

- 首次使用先展示《用户服务协议》《隐私政策》，用户主动勾选后才创建/初始化正式用户数据。
- 协议保存版本号。后续提高 `TERMS_VERSION` 或 `PRIVACY_VERSION` 后，老用户会再次进入确认页。
- “我的”可随时进入用户协议、隐私政策、账号与数据。
- 用户可分别清除：执行历史、身体/运动/营养数据、饮食数据、历程笔记。
- 用户可输入“永久注销”执行账号注销；关联云文件、个人数据、好友关系等由服务端级联删除或按生命周期最小化匿名处理。
- 默认不再把陌生用户自动添加为管理员好友；反馈入口与好友关系分离。

## 三、微信后台《小程序用户隐私保护指引》

代码页不能替代微信后台隐私指引。正式提审前，请在公众平台逐项按实际功能填写，至少核对：

1. 昵称、头像：资料页由用户主动设置/选择。
2. 图片/媒体：笔记、饮食、反馈图片会调用媒体选择能力并上传云存储。
3. 保存到相册：复盘海报仅在用户主动点击“保存”时调用。
4. 订阅消息：计划提醒、社交提醒在用户主动开启/触发时请求微信订阅授权。
5. 云开发数据：计划、打卡、好友/群组、健康/饮食等实际由部署环境保存。

`miniprogram/app.json` 已开启 `__usePrivacyCheck__`。当前代码不自定义微信平台隐私弹窗，优先使用微信官方隐私授权流程；因此后台隐私保护指引必须与真实调用保持一致。

## 四、当前代码中需要真机检查的隐私相关 API

发布前可重新执行：

```bash
rg -n "wx\\.(chooseMedia|saveImageToPhotosAlbum|requestSubscribeMessage|getLocation|getClipboardData|chooseAddress)" miniprogram
```

重点真机测试：

- 第一次上传笔记/饮食/反馈图片；
- 第一次保存周报/月报/90 天海报；
- 第一次请求订阅消息；
- 拒绝某一权限后，其他不依赖该权限的基础功能仍可正常使用。

## 五、健康数据

身体、体脂、围度、饮食、运动等按较高隐私标准处理：

- 默认不向好友公开明细；
- 隐私政策明确说明用途；
- 产品文案不得把估算结果表述为医疗诊断；
- 用户可单独清空健康数据，不要求注销整个账号。

## 六、Free / Beta Pro / Lifetime Pro

- `FREE`：基础任务、长期目标、计时、打卡、日历、基础纪念章、社交和基础健康记录长期可用。
- `BETA`：首次命中公测服务后获得 90 天 Pro，结束时不扣费、不删历史数据，自动回到 Free。
- `LIFETIME`：未来正式支付成功后由可信服务端履约，把 `users.proLifetime=true`；永久权益优先于 Beta 到期时间。
- 公测结束后将 `BETA_ENROLLMENT_ENABLED=false`，已有公测用户的到期时间不会改变。

## 七、支付预留原则

当前版本 **不执行真实收费**。`PRO_PURCHASE_ENABLED=false` 时，Pro 页只展示权益和未来买断说明。

正式收费前：

1. 先在微信公众平台确认当前主体/服务类目实际可开通的虚拟支付能力；
2. 创建并发布永久 Pro 对应的虚拟商品/道具；
3. 服务端生成/签名订单；
4. 客户端只负责拉起官方支付；
5. **只以微信服务端可信支付/发货结果履约**，不能信任客户端“支付成功”字符串；
6. 订单必须幂等，重复回调不得重复发货；
7. 履约成功后再写 `proLifetime=true`；
8. 完成退款、查单、异常恢复和真实订单验收后，才把 `PRO_PURCHASE_ENABLED=true`。

不要把“加个人微信转账后手工改数据库”作为对外售卖路径。人工改 `proLifetime` 只适合公测补偿、赠送、客服纠错，不应与私下付款挂钩。

## 八、上线前最终人工验收

- [ ] 运营者姓名和隐私联系方式均为真实信息。
- [ ] 微信后台隐私保护指引已与当前 API 使用一致。
- [ ] 新账号不同意协议时不会进入产品、不会创建业务记录。
- [ ] 同意协议后可以正常使用，协议更新后会重新确认。
- [ ] 账号注销后重新进入会被视为新用户，并重新确认协议。
- [ ] Free 账号无法读取 Pro 深度报告，但原始基础记录仍可查看。
- [ ] Beta 到期后自动回到 Free，不删除记录。
- [ ] Lifetime Pro 在 Beta 到期后仍保持 Pro。
- [ ] 默认管理员好友不再自动创建，老版本默认管理员保护已解除。
- [ ] 支付开关在未完成官方支付接入时保持关闭。
