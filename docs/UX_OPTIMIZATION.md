# 点击响应与可靠性优化（未发布）

本轮优先减少重复网络往返和页面重绘，沿用黑白灰、低饱和绿的现有风格。不新增每日必填字段，不启用真实支付，不执行云端部署或历史数据清理。

## 用户可感知的变化

- 普通任务完成、撤回先反馈本地状态，同步失败仅恢复该任务，不覆盖其他已成功操作。同步中不能重复点击同一任务。
- 心情、小记和任务备注保存后直接应用服务端结果；普通完成、计时暂停/恢复不再固定重载整个首页。目标归档、兼容旧云端响应时仍会刷新。
- 切回今日页、日历和进步页面时复用短期缓存；保留已经显示的内容，刷新失败提供轻量重试。下拉刷新和点击重试强制读取服务器。
- 新建执行任务以名称、执行频率为主，时间可选，数量和计时等高级设置收起；提供阅读、运动、背单词快捷填充。编辑旧任务保留原配置。
- 今日任务备注、整日心情小记和考试复盘有本地草稿；关闭面板或暂时离开后可以恢复，成功保存才清除。心情仍可留空。

## 请求缓存

缓存仅保存在本次小程序进程内，最多 32 项，不把业务结果写入本地长期存储。

| 读取 | 有效期 |
| --- | --- |
| 今日首页、任务列表 | 15 秒 |
| 日历、当天详情、进步目标、成长纪念、权益概览 | 30 秒 |
| 周/月报告 | 60 秒 |
| 好友申请摘要 | 10 秒 |
| 全局计时状态 | 2 秒 |

相同只读请求合并；结果返回独立副本，页面装饰字段不会污染缓存。所有写操作在开始和结束时清空缓存，失败也清空；较早发出的读取不能重新写回旧缓存。计时视图的服务器时间按校正后的时钟继续前进，不会被缓存时间拉回。

缓存只降低当前客户端的重复读取，好友远端变更最迟在缓存过期或主动刷新后可见。本轮没有引入持久化日汇总集合或服务器报告缓存。

## 服务端和历史记录

- 首页复用长期目标上下文中的任务列表，不重复读取；长期目标的完成记录按关联任务分批查询，成就计算复用已取得的记录。
- 首页读取消息时不再执行消息保留清理循环；消息中心和通知写入路径仍执行原保留规则。
- 连续打卡统计在确认断档后停止分页，不再每次遍历全部历史。
- 当前业务日期由服务器时间和用户保存的时区确定。今日写入日期不一致时提示刷新；日历查询、编辑已存在的过去小记、昨天补签使用明确的历史日期字段。
- 今日刷新跨天或切换用户时，不复用旧日任务状态。迟到任务结果不覆盖较新的完成记录和心情小记。
- 新任务打卡使用用户、任务、日期的固定记录标识与事务；已有随机标识原地更新。自动/手动整日打卡也共享固定标识，保留心情、小记和最初打卡时间。已有重复历史不会在本轮被物理删除。
- 日历和补签优先读取当日任务快照、历史排期及完成快照；考试归档按历史关联累计，不以当前改名、数量或排期反推过去。
- 旧日期无法核实排期时仅展示已知记录，明确标注覆盖不足；不会凭空增加漏做任务。既有考试归档快照仍保持冻结，不批量重算。

## 草稿与安全边界

草稿仅存当前设备，按用户/日期或经过归属验证的目标隔离，最多 20 项、保留 7 天。输入写入做短暂合并，页面离开时落盘；服务器原内容改变时不恢复冲突草稿。注销成功会清空草稿。补签编辑面板本轮未新增草稿恢复。

`admin-init` 改为默认关闭：必须先配置 `ADMIN_INIT_TOKEN`，再携带匹配 token 调用。初始化完成后建议停用函数。Pro 商品配置开关不等于支付已接入，新增 `paymentReady=false` 防止前台误显示可购买状态；没有新建订单、收款或修改用户权益。

## 部署和验收

Schema 仍为 18，没有新集合，本轮优化本身无需运行初始化。先部署新版 `api`，再编译上传客户端；若保留 `admin-init`，同步部署其令牌保护。本轮未修改 `reminder-dispatch`。以前尚未部署的提醒权益变更仍按原发布清单处理。

本地 `npm run verify` 覆盖语法/契约与自动化回归，但不等于微信真机验收。发布前建议在同一设备、同一云环境分别记录优化前后的网络请求数和耗时：

1. 连续点击两项任务、末项自动打卡、撤回、备注保存，检查首次与后续响应。
2. 完成请求超时后重试，同一任务不得重复累计；另一项成功完成不能被回滚。
3. 今日、日历、任务、我的反复切换，检查短缓存；写入后立即进入日历，必须显示新结果。
4. 弱网/断网时检查已有页面、重试和草稿；使用补签卡失败不得扣卡。
5. 修改任务数量/频率、停用或删除后查看昨天并补签，应使用昨天的排期和数量。
6. 模拟零点、手机日期错误和时区，检查服务器日期、今日状态及跨天计时恢复。
7. 真机检查任务创建的折叠字段、快捷模板、计时悬浮条和微信原生授权。授权链路与打卡独立，不能承诺强制隐藏微信弹窗。

云函数冷启动、网络质量和索引仍会影响等待时间；本轮尚未取得真实设备的 P50/P95 延迟数据。
