# 成长复盘与 Pro 提醒升级（未发布）

## 功能与交互

- Free 保留最新完整周的概览：完成次数、有效专注、打卡天数与连续记录；不返回每日分析、身体明细、任务排名或周期对比。
- Pro 支持深度周/月/90 天复盘和历史周期选择。周报回顾完整周一到周日，月报回顾完整自然月，90 天从昨天向前回顾。比较月份时使用完整上一个自然月，并展示日均指标。
- 首屏为四个指标、最多三条小结及一条基于事实的建议；任务表现、长期目标推进、里程碑、趋势和心情默认折叠，没有对应记录时隐藏。
- 心情与小记仍沿用现有可选流程，不新增每日必填字段。报告不推测未完成原因、心理状态或医学结论。
- 趋势展开时才绘图；海报保存/分享时才生成并复用当前周期缓存。海报不包含任务名称、长期目标名称、心情、小记、分数或身体明细。

## 统计口径与兼容

`plans.scheduleHistory` 保存每日生效的执行排期，包含名称、分类、重复规则、执行起止日期、启停状态和目标关联。新建、编辑、启停、软删除、目标绑定和托管任务归档/恢复均保存版本。

`checkins.planSnapshot` 与 `longTermGoalIdsSnapshot` 保留执行当时的信息；`daily_reviews.taskSnapshot` 保存当日打卡的任务快照。完成后同日自动归档的托管任务仍根据执行快照计入报告。编辑已完成任务的小记不改写原执行快照或默认完成量；撤回再完成时才使用新的关联。补卡同样保存快照，不增加用户操作。

- 已知排期的未执行日期计入分母，不再只统计已经打卡的日期。
- 无任务、未完成和无法核实排期分别处理；旧数据不使用后来修改的规则反推，明确显示覆盖范围。覆盖不足时不显示完成率周期差值。
- 灵活“每周 N 次”不按每日重复计入分母；只有完整且规则一致的周结算未完成量。周期边界或中途改规则时只展示实际完成记录，不假设漏做次数，也不计算该任务完成率。
- 固定任务的天数分布与按周次数的完成率是不同口径，页面已说明。连续打卡包含手动、自动、补签与部分完成的日记录，不等同于全部任务连续完成。
- 数量增量只汇总执行当时实际关联的目标，归档后停止计入；没有可靠旧关联记录时不猜测。专注与学习时长分别展示，不相加。
- 分页不再静默止于 1,000 条；月历复用已经查询的整日打卡数据，不重复读取。

## 权益与发送

微信未打卡提醒与特别关心微信推送归入 Pro；活跃 Beta Pro 与永久 Pro 均享有权益。Free 保留站内消息、当天好友动态、特别关心设置、计时到点提醒和原始历史。

前端先检查权益再请求微信订阅；服务端在开启、续订、入队与发送时再次校验。特别关心以**接收者**的会员状态为准。过期只停止高级服务，不删除历史、站内消息或提醒偏好，不补发已跳过的旧消息。

购买仍是占位入口，默认不开启收款，本次不修改已有 Beta 到期日或永久会员标记。

## 部署与验收

需要同时更新 `api`、`reminder-dispatch` 与小程序前端；仅更新前端不能保证权益限制有效。没有新增集合，Schema 保持 18，不必重新运行 `admin-init` 或批量回填旧日期。

运行 `npm run verify`。真机建议覆盖：

1. Free 用户执行任务、普通打卡、补卡不弹升级或微信订阅；设置面板仍可开启消息中心提醒，主动点击微信 Pro 入口才说明权益。
2. Beta/Lifetime 用户照常续订；模拟 Beta 到期后，在消息入队与发送之间确认微信不再推送，站内消息仍存在且偏好保留。
3. 最新 Free 周度概览可读；月报、90 天、历史深度报告入口显示轻量 Pro 说明，不能通过旧趋势接口取回高级内容。
4. 七天每日任务只完成一天：排期已知时为 1/7；“每周三次”完成两次：完整周为 2/3，跨月边界不假定漏做。
5. 修改频率、停用、删除及托管归档后，过去的排期和最后一次完成仍正确；旧排期无法确定时显示覆盖范围。
6. 月报比较完整自然月，二月、大小月、跨年均正确；历史切换忽略晚到请求。
7. 折叠详情、切换趋势、生成/保存/分享海报在真机上验证；相册拒绝、Canvas 异常和快速切换不应卡住页面或复用旧海报。

目前没有持久化报告缓存或日汇总，仍为实时聚合；大规模数据的查询成本属于后续优化。
