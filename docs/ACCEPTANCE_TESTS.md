# 1.6.0 验收测试清单

## 首次使用与版本
- [ ] 新用户首次进入可自动创建用户、隐私和营养档案。
- [ ] 数据库未初始化/Schema 过旧时 API 明确拒绝执行。
- [ ] “关于与诊断”显示客户端/服务端 1.6.0、Schema 9。

## 计划专注计时
- [ ] 创建计划时可选择不计时、正计时或倒计时，倒计时限制为 1～1440 分钟。
- [ ] 正计时支持开始、暂停、继续和结束，并正确区分有效、总用时和暂停时间。
- [ ] 倒计时暂停后不递减，达到有效时间目标后自动结束。
- [ ] 切换导航栏或重新进入小程序后，正在进行的计时能按服务端时间恢复。
- [ ] 同一时间不能同时启动两个计划计时器。
- [ ] 结束计时后直接完成任务，之后点击已完成任务可以补充可选备注。

## 自律日历
- [ ] 小程序启动后默认进入“日历”，底部导航保持 5 项。
- [ ] 完成最后一项今日计划后自动打卡、更新连续天数，并自动弹出整日心情与今日小记。
- [ ] 日历只使用整日打卡心情作为当天的黑白像素印记。
- [ ] 点击日期在当前页面打开详情浮层，点击遮罩空白处关闭。
- [ ] 当天备注小记及图片默认直接显示，完成任务默认折叠且可展开。
- [ ] 展开的任务显示分类、完成时间、有效/总/暂停时间和可选备注。

## 用户反馈与版本公告
- [ ] 普通用户可以提交文字、最多 3 张截图和可选联系方式。
- [ ] 重试同一个 clientMutationId 不会重复创建反馈。
- [ ] 用户只能读取自己的反馈和处理状态。
- [ ] 配置的反馈管理员会收到消息中心提醒，并能读取反馈管理页。
- [ ] 非管理员无法调用反馈管理接口。
- [ ] 管理员修改状态后，提交用户会收到消息中心通知。
- [ ] 同一个版本公告 id 对同一用户只投递一次。

## 身体与营养
- [ ] 体重必填，体脂可选。
- [ ] 围度项目来自 `body_metric_defs`，用户可选择需要跟踪的指标。
- [ ] 指标选择保存到 `body_metric_preferences`，再次进入仍保持。
- [ ] 新体重保留历史，不覆盖旧记录。
- [ ] 超过 7 天未更新体重时，“我的”身体数据入口显示提醒。
- [ ] 更新体重后生成新的营养目标版本。
- [ ] 保存身体记录后可以继续创建关联体态日志。

## 饮食
- [ ] 可搜索系统食物、创建自定义食物。
- [ ] 输入克数实时预览热量和三大营养素。
- [ ] 服务端按食物快照保存历史营养数据。
- [ ] 每次进食自动保留时间戳，不强制选择早中晚餐。
- [ ] 可只用文字或最多 3 张照片记录一次进食。

## 运动
- [ ] 无体重时提示先记录体重。
- [ ] MET 热量计算与 Domain 测试一致。
- [ ] 力量训练可记录重量/次数/组数。
- [ ] 关联计划达到目标后自动打卡并同步群组。
- [ ] 每条运动记录可创建关联训练复盘。

## 学习
- [ ] 可记录科目、内容、时长。
- [ ] 关联计划达到目标后自动打卡。
- [ ] 每条学习记录可创建关联学习笔记。

## 日志与体态照片
- [ ] 支持日常/体态/学习/训练/饮食五类。
- [ ] 支持最多 9 张相机/相册图片。
- [ ] BODY 类型图片可以设置正面/侧面/背面/普通照片。
- [ ] 未保存日志退出后可以恢复本地草稿。
- [ ] 网络失败重试时复用 clientMutationId，不重复创建 Note。
- [ ] 日志可编辑、删除；删除时附件记录同步清理。
- [ ] 其他用户、好友、群组均没有读取 Note 的 API。

## 好友与群组
- [ ] 发送好友申请后，对方收到消息中心通知，圈子标签及好友入口显示红点。
- [ ] 对方可以接受或拒绝；申请方可在处理前撤回，处理结果会通知申请方。
- [ ] 同一申请人在被拒绝 24 小时内、主动撤回 5 分钟内不能反复发送申请。
- [ ] 接受好友后提示当前使用统一好友隐私设置，并可进入“我的”调整。
- [ ] 点击好友进入资料页，只显示对方允许公开的打卡记录，绝不返回任务备注、整日心情或小记。
- [ ] 好友右上角可设置仅本人可见的备注、特别关心、微信提醒和“我向 TA 公开”的单好友权限例外。
- [ ] 单好友权限关闭时跟随全局设置，特别关心不能绕过对方隐私。
- [ ] 删除好友会同时关闭双方特别关心并删除双方单好友设置。
- [ ] 好友仅看到隐私设置允许的状态。
- [ ] 群组仅强制公开绑定计划的执行情况。
- [ ] 群组列表显示人数和群组 ID，复制按钮不误触进入详情。
- [ ] 邀请面板可多选好友或输入个人 ID；对方消息中心收到邀请，确认后加入，同日重复邀请不会重复写消息。
- [ ] 群组详情不再重复显示邀请码卡片和成员标题说明，微信订阅卡片位于最下方。
- [ ] 未完成成员置顶并按完成比例升序；无绑定计划居中；全部完成成员灰度沉底，群主身份仍可辨认。
- [ ] 点击群成员进入当月打卡日历，只显示本群绑定任务名称和完成进度，不返回心情、备注、小记或计时详情。
- [ ] 同群关系不能读取体重、饮食、日志或体态照片。
- [ ] 完成绑定计划后，无论是否订阅微信消息，群详情和其他成员消息中心都会出现记录。
- [ ] 打卡动态默认折叠，展开后显示具体记录、时间戳和点赞按钮。
- [ ] 群成员可点赞或取消点赞有效打卡动态，撤回的动态不可点赞。
- [ ] 好友设为特别关心后，即使不在同一群，也能在圈子首页看到其获准公开的打卡。
- [ ] 撤回已完成任务后，当日自动打卡和日历印记同步取消，群内显示撤回状态；重新完成可恢复。
- [ ] 群组和特别关心的微信提醒均需用户点击开关授权；长期模板保持开关，一次性模板发送后自动关闭。

## 计划提醒与消息中心
- [ ] 计划可以开启/关闭提醒并保存提醒时间。
- [ ] 到达提醒时间但已经打卡时不生成消息。
- [ ] 指定星期、结束日期和每周次数完成状态均能阻止无效提醒。
- [ ] 同一计划同一天重复执行定时函数只生成一条消息。
- [ ] 今日页右上角是消息中心唯一常用入口：有未读显示红点，全部已读后恢复灰色图标。
- [ ] 消息列表中未读项高亮、已读项变灰，并支持单条和全部已读。
- [ ] 每名用户最多保留最近 20 条通知，第 21 条写入后最旧通知被清理，旧版本公告和同日提醒不会因此重复出现。
- [ ] 用户主动同意订阅后可以收到一次微信服务通知。
- [ ] 微信提醒发送成功或无订阅权限后，计划不再显示为已订阅下一次提醒。
- [ ] 拒绝微信订阅不影响站内消息中心提醒。

## 趋势与复盘
- [ ] 7/30/90 天切换后日期范围和摘要同步变化。
- [ ] 体重、体脂仅使用实际记录点绘图，缺失日期不会被当作 0。
- [ ] 未记录饮食的日期不参与平均摄入和热量平衡计算。
- [ ] 运动与学习趋势分别显示，单位为分钟。
- [ ] 月份切换正确处理跨年和不同月份天数。
- [ ] 活跃日历汇总饮食、运动、学习、身体记录和计划打卡。
- [ ] 空数据状态不会报错，并给出明确提示。

- [ ] `npm run verify` 全部通过。
- [ ] 所有 Action 文件低于质量门禁上限。
- [ ] 客户端所有 `api.call()` 均能找到服务端导出 Action。
- [ ] 页面不得绕过 `utils/api.js` 直接调用云函数。
- [ ] App/Cloud/admin-init 版本与 Schema 一致。
