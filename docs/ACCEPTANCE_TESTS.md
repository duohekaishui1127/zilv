# 1.3.0 验收测试清单

## 首次使用与版本
- [ ] 新用户首次进入可自动创建用户、隐私和营养档案。
- [ ] 数据库未初始化/Schema 过旧时 API 明确拒绝执行。
- [ ] “关于与诊断”显示客户端/服务端 1.3.0、Schema 6。

## 计划专注计时
- [ ] 创建计划时可选择不计时、正计时或倒计时，倒计时限制为 1～1440 分钟。
- [ ] 正计时支持开始、暂停、继续和结束，并正确区分有效、总用时和暂停时间。
- [ ] 倒计时暂停后不递减，达到有效时间目标后自动结束。
- [ ] 切换导航栏或重新进入小程序后，正在进行的计时能按服务端时间恢复。
- [ ] 同一时间不能同时启动两个计划计时器。
- [ ] 结束计时并确认后才完成打卡，并同步到对应学习/运动分类记录。

## 自律日历
- [ ] 小程序启动后默认进入“日历”，底部导航保持 5 项。
- [ ] 有心情的打卡日期显示对应黑白像素图标，无心情打卡显示完成印记。
- [ ] 同一天多个心情时使用最后一次完成任务的心情。
- [ ] 点击日期在当前页面打开详情浮层，点击遮罩空白处关闭。
- [ ] 当天备注小记及图片默认直接显示，完成任务默认折叠且可展开。
- [ ] 展开的任务显示分类、完成时间、有效/总/暂停时间、心情和备注。

## 用户反馈与版本公告
- [ ] 普通用户可以提交文字、最多 3 张截图和可选联系方式。
- [ ] 重试同一个 clientMutationId 不会重复创建反馈。
- [ ] 用户只能读取自己的反馈和处理状态。
- [ ] 配置的反馈管理员会收到消息中心提醒，并能读取反馈管理页。
- [ ] 非管理员无法调用反馈管理接口。
- [ ] 管理员修改状态后，提交用户会收到消息中心通知。
- [ ] 同一个版本公告 id 对同一用户只投递一次。

## 身体与营养
- [ ] 体重必填，体脂可选。
- [ ] 围度项目来自 `body_metric_defs`，用户可选择需要跟踪的指标。
- [ ] 指标选择保存到 `body_metric_preferences`，再次进入仍保持。
- [ ] 新体重保留历史，不覆盖旧记录。
- [ ] 超过 7 天未更新体重首页提醒。
- [ ] 更新体重后生成新的营养目标版本。
- [ ] 保存身体记录后可以继续创建关联体态日志。

## 饮食
- [ ] 可搜索系统食物、创建自定义食物。
- [ ] 输入克数实时预览热量和三大营养素。
- [ ] 服务端按食物快照保存历史营养数据。

## 运动
- [ ] 无体重时提示先记录体重。
- [ ] MET 热量计算与 Domain 测试一致。
- [ ] 力量训练可记录重量/次数/组数。
- [ ] 关联计划达到目标后自动打卡并同步群组。
- [ ] 每条运动记录可创建关联训练复盘。

## 学习
- [ ] 可记录科目、内容、时长。
- [ ] 关联计划达到目标后自动打卡。
- [ ] 每条学习记录可创建关联学习笔记。

## 日志与体态照片
- [ ] 支持日常/体态/学习/训练/饮食五类。
- [ ] 支持最多 9 张相机/相册图片。
- [ ] BODY 类型图片可以设置正面/侧面/背面/普通照片。
- [ ] 未保存日志退出后可以恢复本地草稿。
- [ ] 网络失败重试时复用 clientMutationId，不重复创建 Note。
- [ ] 日志可编辑、删除；删除时附件记录同步清理。
- [ ] 其他用户、好友、群组均没有读取 Note 的 API。

## 好友与群组
- [ ] 好友仅看到隐私设置允许的状态。
- [ ] 群组仅强制公开绑定计划的执行情况。
- [ ] 同群关系不能读取体重、饮食、日志或体态照片。

## 计划提醒与消息中心
- [ ] 计划可以开启/关闭提醒并保存提醒时间。
- [ ] 到达提醒时间但已经打卡时不生成消息。
- [ ] 指定星期、结束日期和每周次数完成状态均能阻止无效提醒。
- [ ] 同一计划同一天重复执行定时函数只生成一条消息。
- [ ] 消息中心显示未读数量，支持单条和全部已读。
- [ ] 用户主动同意订阅后可以收到一次微信服务通知。
- [ ] 微信提醒发送成功或无订阅权限后，计划不再显示为已订阅下一次提醒。
- [ ] 拒绝微信订阅不影响站内消息中心提醒。

## 趋势与复盘
- [ ] 7/30/90 天切换后日期范围和摘要同步变化。
- [ ] 体重、体脂仅使用实际记录点绘图，缺失日期不会被当作 0。
- [ ] 未记录饮食的日期不参与平均摄入和热量平衡计算。
- [ ] 运动与学习趋势分别显示，单位为分钟。
- [ ] 月份切换正确处理跨年和不同月份天数。
- [ ] 活跃日历汇总饮食、运动、学习、身体记录和计划打卡。
- [ ] 空数据状态不会报错，并给出明确提示。

## 工程质量
- [ ] `npm run verify` 全部通过。
- [ ] 所有 Action 文件低于质量门禁上限。
- [ ] 客户端所有 `api.call()` 均能找到服务端导出 Action。
- [ ] 页面不得绕过 `utils/api.js` 直接调用云函数。
- [ ] App/Cloud/admin-init 版本与 Schema 一致。
