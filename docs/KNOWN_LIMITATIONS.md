# 已知边界与下一步

1. 公共食物库仍是基础参考数据，未来若扩大应接入来源明确、许可合适的完整营养数据源。
2. 食物检索仍是云数据库正则，数据达到万级以上应使用搜索索引。
3. 运动消耗是 MET 模型估算，不是医学级测量。
4. 身体历史仍以列表为主，下一阶段适合增加体重/体脂/围度趋势图和体态照片对比。
5. Notes 当前只私密可见；未来若增加分享，必须新增显式权限模型，而不能复用群组强监督规则。
6. 图片上传成功但用户从未成功提交 Note 的极端情况下可能留下孤儿云文件，未来可增加定时垃圾回收。
7. 群组详情仍面向三五好友设计，成员扩大后需要引入 `group_daily_stats` 聚合，消除 N+1 查询。
8. 趋势与月历仍实时聚合，已移除单类区间 1000 条的静默截断；数据规模扩大后仍需要日汇总、游标分页或持久化报告快照。旧日期若缺少排期历史，会明确显示覆盖范围，不能可靠反推过去。
9. 已提供分类数据清空与账号注销；自助数据导出尚未接入，删除流程仍需持续验收。
10. 已有用户协议与隐私政策页面，公开发布前仍需配置真实运营主体和联系信息，并验收数据生命周期管理。
11. 微信未打卡提醒和特别关心微信推送属于 Pro。一次性订阅可在正常打卡等点击中尝试补充授权，但仍受微信授权次数限制；用户不操作时不能保证次日继续微信推送，站内消息不受影响。
12. 定时任务已分页读取符合条件的记录；用户规模扩大后仍需要任务分片，避免全量扫描和逐个处理带来的超时。
