# 1.6.0 已知边界与下一步

1. 公共食物库仍是基础参考数据，未来若扩大应接入来源明确、许可合适的完整营养数据源。
2. 食物检索仍是云数据库正则，数据达到万级以上应使用搜索索引。
3. 运动消耗是 MET 模型估算，不是医学级测量。
4. 身体历史仍以列表为主，下一阶段适合增加体重/体脂/围度趋势图和体态照片对比。
5. Notes 当前只私密可见；未来若增加分享，必须新增显式权限模型，而不能复用群组强监督规则。
6. 图片上传成功但用户从未成功提交 Note 的极端情况下可能留下孤儿云文件，未来可增加定时垃圾回收。
7. 群组详情仍面向三五好友设计，成员扩大后需要引入 `group_daily_stats` 聚合，消除 N+1 查询。
8. 趋势与月历仍实时聚合，单类区间记录最多读取 1000 条；数据规模扩大后可生成持久化日报/月报快照。
9. 尚未接入数据导出、账号注销和全量个人数据删除。
10. 公开发布前还需用户协议、隐私政策和更完整的数据生命周期管理。
11. 普通小程序的微信提醒采用一次性订阅，成功发送一条后需要用户再次主动订阅；站内消息不受此限制。
12. 当前定时任务单次最多扫描 100 个启用提醒的计划，用户规模扩大后需要游标分页或任务分片。
