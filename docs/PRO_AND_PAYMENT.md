# Pro 与支付预留设计

## 产品原则

**Free 帮用户执行今天，Pro 帮用户看见长期变化。**

基础执行能力不以“卡住用户”为商业化手段；Pro 的核心价值集中在长期复盘、分享和成长档案。

## 权益层

### Free

- 任务 / 长期目标
- 今日执行
- 基础正计时 / 倒计时
- 日历与基础打卡
- 基础纪念章及获得日期
- 好友与群组
- 基础健康记录
- 隐私、数据清除、账号注销
- 补签卡：最多 3 张，每月恢复 1 张

### Pro

- 周报 / 月报 / 90 天复盘
- 周期对比和高级趋势
- 总结海报保存与分享
- 完整成长档案与稀有纪念章详情
- Recovery+：最多 6 张补签卡，每月恢复 2 张
- 后续高级主题和深度复盘能力

## Beta Pro 生命周期

```text
首次进入公测版
  -> betaStartedAt
  -> betaExpiresAt = +90 天
  -> source=BETA

90 天到期
  -> source=FREE
  -> 不删除历史数据
  -> 深度报告等高级入口锁定

正式买断成功（无论 Beta 是否到期）
  -> proLifetime=true
  -> source=LIFETIME
  -> 立即恢复全部 Pro 权益
```

## 为什么不把私下转账设计进代码

永久 Pro 属于数字/虚拟权益。正式售卖应以微信后台当时允许的官方虚拟支付能力为准。私聊转账 + 手工改库缺少平台订单、退款、对账和可信履约链，也可能触碰平台对虚拟商品付费路径的限制。

人工授权 `proLifetime=true` 可以保留为运营/客服能力，但仅用于：

- 公测补偿；
- 内部测试；
- 合法活动赠送；
- 客服纠正异常订单。

正式购买应新增独立 `pro_orders`/订单存储和服务端支付回调，再把永久权益发放与可信订单绑定。当前 Schema 18 **尚未建立支付订单集合**，这是刻意的：公测阶段没有真实支付，不提前引入无法真实验收的支付状态机。
